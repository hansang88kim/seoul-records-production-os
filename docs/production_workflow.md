# Seoul Records 제작·배포 워크플로

| 단계 | 작업 | 확인할 산출물 |
|---|---|---|
| Song Lab · Suno | 앨범 콘셉트, 언어·무드, Workspace, 트랙 순서와 곡별 기본값을 지정합니다. 초안 제목·스타일·가사를 검토하고 사용할 버전을 선택합니다. | [Suno 기본값](suno_defaults.md), 트랙 목록, 개별 원본 WAV, 가사 원문 |

| YouTube Package | 동일 영상의 챕터·선택 썸네일로 제목과 설명을 검토합니다. 비공개 업로드 후 Studio에서 최종 설정과 영상 상태를 확인합니다. | 최종 제목·설명, 비공개 영상과 썸네일, 확인한 공개 상태 |

프로젝트별로 곡 번호·정식 제목·원본 파일·가사·연주 구간·음절 시작과 마지막 발성 시간을 같은 트랙에 기록합니다. 제작 프리셋 버전과 선택 이미지·브랜드 자료도 작업에 연결합니다. GitHub에는 재사용 가능한 절차·설정·코드를 올립니다. 실제 음원, 초안 링크, 프로젝트 증빙과 로그인 자료는 각 작업 계정의 접근 제어 아래 보관합니다.

## 매 요청 실행과 이어하기

- 요청을 받으면 시리즈명·권호와 요청한 범위를 확인합니다. 곡 순서·타이틀곡·Workspace·보컬 구성·이미지 등 이미 확정한 사항과 저장된 산출물을 가져옵니다. 새 결정이 없는 항목에는 프로젝트 기본값을 적용합니다.
- 같은 날 두 요청도 권호별로 작업 폴더와 기록을 구분합니다. 같은 권호의 후속 요청은 기존 작업에서 이어갑니다. 생성·렌더·전송이 진행 중이면 해당 작업의 상태를 확인하고 완료된 산출물을 재사용합니다.
- 순번, 정식 제목, 선택한 Suno 버전, 개별 WAV 경로와 길이, 가사 타이밍을 곡별로 연결합니다. 최종 순서 하나를 렌더·YouTube 챕터·UnitedMasters 등록에 사용합니다. 사용자가 순서를 바꾸면 세 산출물을 다시 대조합니다.
- 단계가 끝날 때 확인 시각과 산출물 경로, 현재 상태 및 다음 작업을 프로젝트 기록에 남깁니다. 기존 `playlist_plan.json`, `render_plan.json`, `chapters.txt`, `upload_result.json`, `tracklist.csv`, `release_metadata.json`을 연결합니다. 외부 결과 ID와 승인 기록은 접근이 제한된 프로젝트 위치에 둡니다.

| 재개할 단계 | 먼저 확인할 기록 | 완료 기준 |
|---|---|---|
| 곡 준비 | 권호, 확정한 곡 수·타이틀곡·순서, 선택한 Suno 버전 | 각 곡에 개별 원본 WAV가 있고 파일명·길이·형식을 대조했습니다. |
| 이미지·영상 | 선택한 사진, 16:9 썸네일과 영상 배경, 1:1 배포 커버, 타이밍 JSON | 미리보기의 가사·간주와 첫 곡 전환을 검수했습니다. 최종 영상, 실제 챕터, 곡 수와 순서를 확인했습니다. |
| YouTube | 채널, 기존 권호, 업로드 상태와 영상 ID | 제목·설명·챕터·썸네일을 확인했고, 비공개 저장과 HD 처리를 확인했습니다. |
| UnitedMasters | 아티스트, 기존 릴리스·초안 ID, 각 곡의 전송과 필수 입력 상태 | 한글 WAV·곡 제목, 커버, 순서·길이, 전곡 크레딧을 검증했습니다. 제출 요청까지 수행한 경우 승인된 발매일과 제출 성공을 확인했습니다. |

전송 도중 끊겼거나 완료 응답을 못 받았으면 먼저 플랫폼의 목록과 상세 화면을 확인합니다. 이미 올라간 영상이나 음원은 기존 항목에서 이어갑니다. 실제로 실패한 항목만 재시도합니다. 재시도 뒤에는 곡 누락이나 중복이 없는지 확인합니다. 최종 보고에는 권호별 영상·커버 링크와 YouTube 공개 상태, UnitedMasters의 초안·제출·공개 중 확인된 상태를 기록합니다.

## 썸네일과 영상 배경

- ChatGPT에서 실제 이미지 후보를 번호와 콘셉트 한 줄씩 붙여 보여줍니다. 지시가 있으면 후보 수를 조정합니다. 후보마다 구도·인물 포즈·카메라 거리·조명 중 하나 이상을 바꿉니다.
- 프롬프트에는 인물·공간·행동·거리·빛·질감·텍스트 여백을 적습니다. 레트로 실사에서는 1990년대 서울의 오락실, 레코드 숍, 비 오는 전화부스처럼 구체적인 장소를 쓰고, 표정과 피부 톤은 자연스럽게 표현합니다.
- 캠퍼스 예시에는 교실 오른쪽 발표자, 중앙의 큰 프로젝터 화면, 왼쪽 아래에 스마트폰을 든 학생을 배치합니다. 파형과 가사가 들어갈 칠판 하단, 트랙 목록을 위한 아랫단, 우하단 브랜드 공간을 비워 둡니다.
- 후보의 ID·프롬프트·이미지 파일·비율·수정 이력을 남기고 최종 ID를 기록합니다. 제목·번호·브랜드 글자는 편집 단계에서 올릴 수 있게 분리합니다. 정지 파형이 포함된 썸네일을 확정했으면 영상용 배경에는 파형 자리를 비워 둡니다.
- 같은 사진에서 플랫폼별 이미지를 준비합니다. YouTube 썸네일은 16:9에 제목을 넣고, 영상 배경은 사진의 적절한 여백에 자막과 파형을 얹을 수 있도록 준비합니다. UnitedMasters용 1:1 커버는 [영문 손글씨 배치 기준](unitedmasters_distribution_package.md#11-커버-디자인)을 따릅니다. 가로 원본만 승인됐다면 원본 구도를 유지하는 3000×3000 변환 시안을 확인합니다.

## 캠퍼스 영상 렌더

Video Renderer의 **Seoul Records · 캠퍼스**를 선택하고 검수한 곡 순서를 사용합니다. Thumbnail Studio에서 배경을 고르거나 ChatGPT에서 고른 배경 JPG/PNG를 직접 넣을 수 있습니다. 투명 로고 PNG는 선택입니다. 프리셋과 정확한 수치는 [캠퍼스 설정](../presets/video/seoul_records_campus_v1.json)에 있습니다.

| 요소 | 캠퍼스 기준 |
|---|---|
| 타임라인 | 1920×1080, 30fps. 2초 리드인, 첫 프레임부터 01 제목과 하이라이트 표시 |
| 파형 | `(680,744)`에서 `560×100`, 중심축 `y=794`. 흰색 둥근 캡슐 60개, 3.55px 반지름, 무음 반높이 4.09px, 최대 38.3px. 스테레오 음원 24kHz 분석, Hann 4096, 42–9500Hz 로그 대역 |
| 가사 | `(960,706)`, Jua 54, 연노랑 `#FFE9B6`. 첫 음절 40ms 전에 나타나 음절 시작 때마다 강조. 마지막 음절 후 다음 줄 또는 확인된 연주 구간까지 유지 |
| 연주 구간 | 가사와 같은 위치·크기의 `간주중 ♪`. 실제 전주·간주·후주 구간에 사용합니다. 첫 보컬까지 2초 이내인 전주와 일반 호흡에서는 생략합니다. |
| 곡 제목 | `(960,867)`, Jua 38, 번호와 곡명을 약 3초 표시 |
| 하단 트랙 목록 | 네 열을 각각 위에서 아래로 읽습니다. 19곡이면 `01–05 / 06–10 / 11–15 / 16–19`, 24곡이면 `01–06 / 07–12 / 13–18 / 19–24`입니다. 번호 Space Mono 16, 제목 Jua 22를 기준으로 열 시작 `490, 756, 986, 1234`, 첫 줄 `y=949`, 간격 24px를 사용합니다. 행이 늘면 글자 크기와 여백을 검수합니다. Vol.73은 첫 줄을 `y=931`에 두어 6행을 넣었습니다. 현재 곡만 노란색으로 강조합니다. |
| 곡 전환 | 0.70초 페이드아웃 → 0.30초 무음(30fps에서 9프레임) → 0.10초 페이드인. 전환 무음은 점선 파형과 기본 트랙 목록을 표시 |
| 출력 | H.264, yuv420p, BT.709, 48kHz AAC 스테레오 320kbps, MP4 faststart. 챕터는 첫 곡 `00:00`, 이후 실제 음악 시작 시점 |

캠퍼스 렌더에는 FFmpeg의 `ass` 필터(libass)가 필요합니다. 정확한 서체를 쓰려면 Jua와 Space Mono를 시스템에 설치하거나 `assets/fonts`의 `Jua-Regular.ttf`·`SpaceMono-Regular.ttf`를 사용합니다. 환경에 해당 서체가 없으면 libass가 사용 가능한 서체로 대체합니다.

### 가사 입력 예시

정렬한 타이밍을 **음절·연주 구간 타이밍 JSON**으로 넣습니다. 시각은 각 원본 트랙의 0초를 기준으로 기록합니다. 공백은 음절의 `text`에 포함합니다. 낮은 신뢰도의 구간은 첫 단어, 늘어지는 종결음, 반복 후렴을 실제 음원으로 대조합니다.

```json
{
  "tracks": [
    {
      "track_no": 1,
      "lyrics": [
        {
          "end_sec": 3.2,
          "syllables": [
            {"start_sec": 2.4, "text": "안"},
            {"start_sec": 2.7, "text": "녕"}
          ]
        }
      ],
      "instrumental": [{"start_sec": 0, "end_sec": 2.3}]
    }
  ]
}
```

가사 타이밍은 실제 선택한 WAV와 대조한 값을 입력합니다. 생성 버전에서 반복된 구절에는 각 발성 위치를 따로 기록하고 간주에는 확인한 연주 구간을 넣습니다. 가창을 확인할 수 없는 초안 문구는 타이밍 JSON에서 제외하고 검수 기록에 남깁니다. 60초 미리보기에서 01 하이라이트, 가사와 곡 제목의 위치, 간주의 글자 크기와 짧은 숨 동안의 가사 유지 상태를 확인합니다. 첫 60초에 곡 전환이 없으면 **01 → 02 전환 미리보기**도 확인합니다. 노란 강조 이동, 무음, 곡 순서, 제목 겹침, 챕터 경계를 검수한 뒤 전체 영상을 렌더합니다.

긴 영상은 곡 경계가 고정된 구간별로 렌더하고 완료 구간을 보관할 수 있습니다. 곡별 변경이 있으면 해당 구간을 다시 렌더하고, 전체 배경이나 순서가 바뀌면 영향을 받은 구간을 다시 계산합니다. 전체 렌더 후 최종 MP4의 해상도·프레임레이트·오디오·전체 길이를 확인합니다. 최종 챕터와 각 곡 시작 직후의 재생 강조를 재생 순서와 대조합니다. 여러 구간을 병합할 때 오디오는 앨범 타임라인을 기준으로 한 번 인코딩합니다.

## YouTube 메타데이터와 업로드

1. 최종 MP4 옆의 `chapters.txt`를 사용합니다. 곡 수, 제목, 시작 시간은 렌더 결과에서 가져옵니다. 캠퍼스 챕터에는 리드인과 곡 사이 무음이 들어갑니다.
2. 서울레코즈 한국어 콘텐츠는 `[Playlist]`로 시작하고 장면을 담은 짧은 문구와 이모지 1–2개를 쓴 뒤 `|` 뒤에 실제 장르를 적습니다. 한국 시티팝은 `Korean Seoul City Pop`을 쓰고, 볼륨 번호는 있는 경우에만 붙입니다.
3. 설명에 장면과 듣기 좋은 순간을 적고, 실제 트랙리스트 뒤에 장르·청취 상황·오리지널 제작·사용 허가 FAQ와 확인된 제작/AI 정보, © Seoul Records, 관련 한영 해시태그를 넣습니다. 제작실 설명 초안은 실제 챕터가 있을 때만 `[[TRACKLIST]]`를 한 줄에 한 번 쓰고 제작실이 치환한 결과를 확인합니다. 제목은 100자, 설명은 UTF-8 5,000바이트 이내입니다.
4. 업로드 전에 Seoul Records 채널과 기존 권호 영상을 확인합니다. 최종 MP4·16:9 커스텀 썸네일·챕터를 등록하고, 해당 영상의 언어·카테고리·대상 시청자·AI 사용을 실제 내용에 맞게 선택합니다. Vol.73은 한국어·음악·아동용 아님·AI 사용 예로 등록했습니다.
5. 비공개로 저장한 후 제목·설명·챕터·썸네일, HD 처리 결과와 공개 상태를 Studio에서 확인합니다. 영상 ID와 확인한 링크를 기록합니다. 공개 요청이 있으면 지정한 상태와 시점에 맞춰 별도로 적용하고 확인합니다. [비공개 업로드 세부 절차](youtube_private_upload.md)
